# GZBoost 高速拉升核验（2026-10-04）

## 来源与口径

- 官方 SLM：m1919810/SlimefunHelper，1.21.11 分支提交 `fe5ed1545d7b607746d038a8523da08f0b6753aa`；核验时没有更新的官方提交。
- 测试使用未修改的官方 `SlimefunHelper-1.21.11-1.1.7.2.jar`，SHA-256 `8ab9137b491435379ebb01c22dee01bad420e3203556ca27bdb255fbe7cca451`。
- Rime 基线：`6604120624f56615824ce95995f3dcc6d81326b9`（1.2.12）。
- 独立本地 Paper 1.21.11 build 132、Grim 2.3.73、PacketEvents 2.14.0、ViaVersion/ViaBackwards 5.12.0；客户端 ViaFabricPlus 4.4.15 选协议 765（1.20.3/1.20.4）。
- 正常生存模式鞘翅、持续烟花，前进加跳跃；测试夹具只负责装备、初始传送、输入和坐标记录，不在测速中写玩家速度。未测试甲飞、进食、碰撞或 PvP。
- 每组运行约 20 秒，取最后 10 秒**服务端实际高度差 / 单调墙钟时间**。数值不是客户端速度显示、理论包络或瞬时峰值。测试客户端锁 60 FPS 只是实验条件。

## 首轮实测（垂直格/秒）

| 模式 | 沿轴（yaw 0） | 对角（yaw 45） |
| --- | ---: | ---: |
| SLM V5 | 225.416 | 240.346 |
| SLM V5_PULLUP_ONLY | 258.966 | 258.955 |
| Rime 既有激进档 | 213.582 | 203.187 |
| Rime 高速拉升候选 | 237.685 | 254.105 |

首轮这些高速组末段均持续滑翔，未出现单 tick 向下超过 2 格的跳变；这项统计不等于不存在服务端纠正。V3/V4 在同环境出现失速/纠正，因此不将高速结论泛化到所有 SLM 模式。复测使用 Grim EventBus 原始 FlagEvent 观察器，不依赖有阈值的控制台报警。

## 复测与波动

| 模式 | 沿轴 | 对角 |
| --- | ---: | ---: |
| SLM V5 | 188.849 | 176.614 |
| SLM V5_PULLUP_ONLY | 258.789 | 229.814 |
| Rime 既有激进档 | 213.408 | 204.166 |
| Rime 高速拉升候选 | 237.423 | 254.102 |

该轮 EventBus 观察器使用了 Grim 的 Object 重载，反编译确认该版本此重载是空实现。故该轮“零事件”统计无效并已撤回，不能据此宣称无违规。已改为 BasicGrimPlugin 重载，增加会触发 Simulation 的 V3 对照组验证观察器，再单独复测 Rime 新旧算法。

最终有效观察器在 V3 对照组捕获 **381 次事件**，随后同一客户端依次关闭/开启新选项完成四组测速：

| 最终配对 | 沿轴垂直格/秒 | 对角垂直格/秒 | 测速区间 Grim 事件 | 原版移动过快报警 |
| --- | ---: | ---: | ---: | ---: |
| 既有激进档 | 214.496 | 203.170 | 0 | 0 |
| 开启高速拉升 | 237.655 | 254.147 | 0 | 0 |

最终增益分别约 **10.8% / 25.1%**。零事件只指 START 之后的测速区间，初始传送/准备阶段另有 2 次 Simulation，保留在原始事件 CSV 中，未算入稳定飞行。没有将未监测有效的 SLM 轮次标为零事件。

Rime 新旧算法的两轮结果接近：沿轴增益约 11%，对角约 24%–25%。SLM 复测阶段与完整回归任务存在 CPU 竞争，且出现服务端移动过快报警；因此保留该结果但不用于声称 Rime 比 SLM 更稳定或更强。这不是严格的跨客户端稳定性对比。更换反作弊版本、公网延迟、甲飞和实战胜率仍需单独验证。

执行 `gradlew check` 成功（123 个任务），包含 44,032 项 CoupledCruise 检查和空战连接回归；测试结束后恢复生产编译参数并检查授权动作入口。

## 本次实现

按用户要求直接融合进 GZBoost 激进档，移除了临时的 `GZBoostFastClimb` 开关。使用 `Grim` → `GZBoost` → `Aggressive`，手动方向输入加跳跃时自动采用新拉升算法，无需额外配置。上面的测速是在算法相同、尚有临时开关的候选代码上完成的；集成修改只去掉额外开关条件，保留所有运动安全检查。

融合后生产参数编译通过，CoupledCruise（44,032 项）、空战连接（621 项）与授权动作入口（797 项）回归全部通过；记录中的原测速源码哈希保留，集成源码哈希单独保存在 JSON 的 `integration` 字段。

借鉴 SLM V5 通过水平支撑提高后续滑翔升力的思路，在现有 Rime 包络内比较四个轴向辅助视角，保留驾驶者的输入朝向。没有移植 V5_PULLUP_ONLY 每 tick 的 360 × 4 全方向搜索，也不增加线程或世界扫描。水平速度允许侧移，不承诺严格垂直、精确追击或固定水平航速。

仍经现有实际烟花附着、旧协议能力、旋转提交、碰撞、地形避让和回弹恢复检查；没有附着烟花时不额外施加推力。纯跳跃、下潜、巡航、温和档及空战接管保持原路径。特别是重锤/MXS 的温和拉升、精确攻击与防御方向不被高速拉升替换。运动预测使用相同选择逻辑。
