# 空战追击、回转与重锤蓄伤（2026-10-04）

基线：Rime 1.2.13，`8cab789d402d9f25afd781b2605645d36244e5c0`。
用户反馈：重锤和长矛都存在围着目标上方追逐、攻击频率低的问题，希望把 GZBoost 的速度用于更多高伤害命中。

## 改动

- 追击方向接近平飞时不再由 `diagonalGzBoost` 人为改成爬升。其他追击方向也限制额外俯仰偏离；原本合理的斜向拉升保留。
- 长矛平飞追击保留拦截方向；达到撤离距离或撤离超时后，当拍重新计算追击方向，避免切换状态后还沿旧方向多飞一拍。
- 长矛在撤离边界附近结合实际运动和目标漂移限制最后一段撤离距离。避矛侧移不受这一限制覆盖。
- 重锤接近空中目标的水平／下落顶点时也使用已有精确收速逻辑；目标仍在上升且尚未取得高度差时继续保留拉升推力。可达顶点附近不再强制放大成至少 5 格的请求。
- 重锤保留原有落差、真实距离、视线、发出的转头、收翼、进食及授权检查。原先最多保留一拍的蓄伤窗口，只有连续一拍目标运动稳定、重新预测仍可命中时，才允许再保留一拍。每轮最多两拍；不能由同 tick 的多个回调续期，跳 tick 或目标转向不延长。

这是短距离控制和出手时机调整，没有增加每 tick 世界扫描，也没有直接放开攻击距离或用重复发包冒充有效攻击。手动 GZBoost 的巡航与高速拉升实现保持原样。

## 联机诊断

本机两个独立、冻结的开发运行目录，Paper 1.21.11 build 132、Grim 2.3.73、PacketEvents 2.14.0、ViaVersion/ViaBackwards 5.12.0，ViaFabricPlus 4.4.15 实际选择协议 765。双方同装备、同配置、GZBoost Aggressive、甲飞、MaceHeight 10、MaceMinFallDistance 1.5，各武器两局互换出生边。出生半间距 18，高度 155，高度差 5，方向 32°；单局上限 1200 tick。

两个测试窗口都显式限帧 60，仅为比较环境；这不是产品帧率上限。最终四局双方 FPS 中位数 59–60，服务端平均 TPS 20.00–20.13。测试前后运行 class 哈希一致。基线由同一开发运行目录复制，仅把本轮三个业务源文件恢复为基线提交后重新编译；双方使用仓库现有开发授权流程，没有修改授权实现或制作开发授权发行包。

### 全部试验记录

1. `../duel129-diagnostic134-cycle`：无效。搭建时只执行了开发 `compileJava`，错误复制了生产资源标记，模块没有实际进入战斗。日志中的掉血来自摔落。已停止并保留证据，排除全部数据。
2. `../duel129-diagnostic134-cycle2`：正确执行开发 `classes` 后，验证追击／撤离／顶点收速。重锤一负一平，有效掉血事件 25 对 22，总掉血 81.563 对 81.390，单次均值反而下降；长矛一胜一负，事件 6 对 4，总掉血 46.333 对 33.701。没有把这一版称为整体变强。
3. `../duel129-diagnostic134-cycle3`：增加有硬上限的第二拍蓄伤后再测，结果如下；这是保留的实现。所有早期不利结果同样保留在配套 JSON 中。

| 最终候选 / 同局旧版 | 重锤 | 长矛 |
| --- | --- | --- |
| 候选胜负 | 2 胜 | 1 胜 1 负 |
| 对手有效掉血事件数 | 13 / 12 | 7 / 5 |
| 对手累计掉血 | 65.333 / 44.019 | 55.667 / 43.667 |
| 每事件平均掉血 | 5.026 / 3.668 | 7.952 / 8.733 |
| 同局连续掉血事件间隔中位数（tick） | 39 / 49 | 45 / 28 |

指标取服务端逐 tick 血量下降并限定伤害来源为对手，排除环境摔落。它们不是原始伤害：吸收、图腾、溢出伤害及同期回血都会影响可观察的掉血。每局结束时间不同，不能跨候选轮次直接比较累计数值；表格只比较同局对手。长矛总事件数、累计掉血有改善，但单次掉血和连续事件间隔没有同时改善，不能称为每刀更痛或稳定提速。

这些是同一场景换边的小样本调试结果，不是独立胜率验证，不能据此宣布 100%／75% 胜率或保证所有服务器表现。双方仍可能持续相互拉升；本轮修正了多余爬升和撤离，不宣称消灭所有盘旋。重锤需要服务器认可的真实落差，长矛受蓄力、接触冷却、相对运动和命中判定限制，不能保证每次攻击都是高伤害。
