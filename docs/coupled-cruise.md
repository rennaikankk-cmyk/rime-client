# 耦合巡航（1.21.11）

当前入口为 `GuangxiElytra → Mode=Grim → GZBoost`；下文 Cruise 参数是内部策略参数，旧版设置名保留作算法说明。甲飞换装统一由独立 `ArmorFly` 模块控制，Tricks 中的旧开关在加载旧配置时迁移。巡航总速帽是计算上限，不代表实际能达到的速度，也不是服务器许可值。

本轮使用 v10.4.26 的单视角巡航作为功能参考。原始 `.disabled` + `729.nbt` 仍是空战对打基准，二者没有互换。

## 控制

- WASD 指定水平方向；空格/潜行指定升降。只有升降键时不添加横向驱动，包络要求保留的横向惯性仍会保留。
- 开启 `AutoFly` 后，无方向输入时沿当前巡航航向飞行。未开启且没有输入时，保留原模块的闲置行为。
- 智能爬升角根据水平方向选择角度：轴向约 −60°，45°斜向约 −45°。关闭后使用固定拉升角。
- 高度脉动从当前高度向下巡航，下降到高度窗底部后拉升，回到参考高度后再次下降。参考高度固定，不把每次越顶的余量累加成持续上漂；离散 tick 和惯性仍可能短暂越界。人工升降、停用、配置改变或控制权交接会重置高度窗。
- 下降节流只用于有水平方向的受控滑翔。纯垂直下降和重锤脱翅后的真实下落不经过该节流。
- `CruiseSpeedLog` 每秒在本地聊天栏显示应用速度、垂直速度和脉动状态。数值为客户端应用速度（格/tick），不是服务端测速。

## 参数

| 设置 | 含义 | 默认 |
|---|---|---:|
| CruisePitch | 巡航俯仰角 | 15° |
| CruiseClimbPitch | 关闭智能角后的拉升俯仰角 | −45° |
| CruiseDescentPitch | 受控下降俯仰角 | 30° |
| CruiseSmartClimb | 智能爬升角 | 开 |
| CruiseDescentFloor | 受控下降目标下限 | −1.7 格/tick |
| CruisePorpoise | 高度脉动 | 关 |
| CruiseHeightWindow | 高度窗 | 60 格 |
| CruiseSpeedCap | 总速帽 | 15 格/tick |
| CruiseBoxCap | 局部包络盒帽 | 1.7 |
| CruiseInset | 包络内缩，按各轴实际宽度约束 | 0.002 |
| CruiseDualLook | 双视角（分离运动视角与盒视角） | 开 |
| CruiseDualClimbAngle | 双视角拉升角，0=自动求解 | 0 |
| CruiseDualDiveAngle | 双视角俯冲角，0=自动求解 | 0 |

`manual-coupled-cruise` 预设开启本选项和速度日志，保留地形防护，关闭追击及 AutoFly。加载方法与其他预设相同；加载后手动启用飞行；需要换甲时另开启独立甲飞。

## 控制权和约束

手动/AutoFly 与追击分别提供飞行方向。GZBoost 追击现复用双视角推力、连续位移惯性和速度限制；拉升使用有方向滞回的轴向航线，航向偏离追击方向超过 60° 时重新选择。精确命中、闪避、重锤真实下落、避障/安全恢复、水/岩浆和回弹冷却不会使用追击双视角。旋转被其他请求抢占、烟花未附着或路径检查否决时，不发送该次双视角包。

重锤追击的拉升自动使用 Gentle 角度，减少横向摆动，便于衔接收翼下砸；设置面板中的 GZBoostMode 仍控制手动巡航。该调整不改手动巡航的速度上限或求解公式。精确接近阶段按当前可达到的速度规划收翼窗口，未对齐时先跟随横向运动。

## 双视角（CruiseDualLook，默认开）

参考端 v10.4.26 的双视角移植：拉升/俯冲段额外求解一个"盒视角"（拉升=平视 0°，俯冲=dive pair 解），并在本 tick 移动包之前直发一个同位置、旋转为盒视角的追加转头包；包络盒的第二视线由上一 tick 实际视角改为该盒视角。效果是运动视角可以很陡（滑翔模拟给出强爬升）而水平方向的增长额度仍按"平视"计算——拉升段不再丢弃水平速度。每个 tick 的包序为：pre-tick 重同步（恢复 vanilla 记账视角）→ 追加盒视角包 → 移动包（运动视角），与参考端一致。

能力门（DualViewSupport）：只有客户端 ViaFabricPlus 存在且 Via 目标协议 ≤1.20.7 族时双视角才生效；1.21+ 协议会拒绝/塌缩追加转头包。不满足时自动回退单视角（行为与旧版完全一致），并在每次连接内首次启用时聊天栏提示一次：需安装 ViaFabricPlus 并通过 Via 连接 1.20.7 及以下版本服务器。CruiseDualClimbAngle/CruiseDualDiveAngle 为 0 时按参考端公式自动求解；俯冲 pair 无解的 tick 同样回退单视角。双视角只在垂直意图非零、非纯垂直时激活；纯垂直与水平巡航不受影响。

该功能依赖低版本服务器接受一 tick 双旋转包；对有移动检查的服务器属于既有风险域，参考端的反作弊豁免链（BadPacketsFix/Disabler）未移植。

在实际滑翔计算后，以同一次调用的速度和运动视角求包络。只有烟花已附着、旋转未被其他模块改写、包络与总速帽有交集时才应用；否则保留 vanilla 滑翔。可行性由盒内距原点最近点判断，限速投影始终同时满足盒约束与速度球。下降目标达不到时明确显示，不把向下更快误称为“已减速”。

## 诊断与发布

开启巡航时，飞行摘要配置追加完整的 `coupled` 白名单快照；关闭时仍是旧格式。各 tick 比较快照，防止中途切换设置混入一个统计窗口。无追击的独立巡航也参与采样。

后台标签表示巡航设置已开启，追击始终拥有目标和攻击阶段的控制权。`isCombatBoostApplied` 与 `isCombatDualViewApplied` 可在本机诊断中分别观察推力应用与双视角发送；没有将它们宣称为服务端反作弊验收。

配套后台补丁暂存 `work/coupled-telemetry-dev`，接收器保留旧客户端格式，新增可选但完整校验的 `coupled` 扩展。发版前先部署并核对该服务端补丁，再发布客户端；旧后台会拒绝新扩展并触发既有 400 降级。当前工作未自动部署。

## 验证边界

GLM v2 的原有测试全部通过，但独立探针仍复现 7 项失败：带航向的纯垂直两条、无输入自动巡航、脉动起始/顶点两条、垂直于航向的残余速度误判、非法输入后的状态残留。产品控制器已逐项修正。原型快照和失败日志保存在独立审查目录，未修改失败证据。

产品回归还覆盖真实滑翔计算驱动的高度循环、旋转交接、有限大数、非单位视线、窄盒内缩和固定种子的逐轴/总速约束。完整构建及保护项校验通过；游戏内验证结果在交接报告记录。尚不能由这些结果推出实服速度优势、空战胜率提升或“全面超越”。

2026-09-19 本地原版服独立功能验证：水平巡航、斜向拉升、纯垂直上升均运行，纯垂直最后 100 个样本横移为 0。12 格高度窗最初实测 22 次往返累计上漂约 31.36 格；固定参考高度后，35 次转入下降的高度跨度为 1.62 格。关闭选项后的 161 tick 记录没有巡航接管。离散越顶仍存在，未声称严格固定在 12 格内。汇总见 `cruise-functional-trials.json`；原始双端 CSV 在本地实验目录保存。

本轮测试为开发启动，帧率上限 60，客户端视距 16/模拟距 12，服务端均为 4；带抗性防摔，仅用于独立飞行，不是与原始 disabled/NBT 的新一轮对战，也不是生产授权/双 JDK/F8 验收。修后完整构建通过：巡航 7743 项、滑翔 60162 项、遥测接线 26 项、混淆 9927 项检查。

2026-09-19 双视角移植：CoupledCruise 增加双视角选择对与盒第二视线（7,821 项检查），新增 DualViewSupport 版本族矩阵（19 项）。追加转头包与重同步的真实服务器行为（≤1.20.7 目标 + 旧协议反作弊）尚未实测，未经对打验证不宣称收益。

## 空战协议验证

2026-09-28 对打使用真实 ViaFabricPlus 4.4.2 → 1.20.3–1.20.4 → ViaProxy → 本机原版 1.21.11 后端，以保留后端原生重锤伤害；旧端继续原来的 1.21.1 → ViaProxy 路线。它不是原生 1.20.4 武器服务器或 Grim 对战验收。ViaBackwards 将重锤显示为下界合金斧，客户端仅凭明确的原始物品标记识别该兼容路径，不将普通斧头或改名物品当成重锤。此前原生 1.21.11 的 GZBoost 单视角败局和未识别武器的协议预检分别保留，不混入正式批次。

最终自动选择 Gentle 的候选以默认 Aggressive 设置完成 10 局：6 胜、3 负、1 平；此前显式 Gentle 的独立批次为 7 胜、2 负、1 平，更早 Aggressive 追击批次为 3 胜、3 负、4 平。各批次代码或配置不同，分别统计，不能合并为同一版本胜率。对手均为原始 SlimefunHelper 1.21.1 `.disabled` 与 `729.nbt`，固定装备、交替换边、本机低延迟；未覆盖高延迟、多人混战或矛模式，也没有重新测量手动巡航的最高速度。
