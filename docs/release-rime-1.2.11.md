# Rime 1.2.11 · Minecraft 1.21.11 · Rimeguard v3.4.0

修复下界自动床因读取未同步的 BED_RULE 而完全不放置的问题。按原版规则支持床头悬空、侧面放置、箱子等交互方块支撑，以及床头超出交互距离时点击床尾引爆。保持服务端方块确认、自伤上限、防自杀及授权检查，Rotate 开关两种状态均有实际客户端/服务端测试。

同时包含本轮字体与 HUD 性能优化：限制容量的文字宽度/排版缓存、GUI 缩放切换时回收旧字形页、复用 HUD 元素查找与外观对象。颜色设置仍即时生效。这里的测量是对应计算路径耗时，不能等同于所有设备的游戏 FPS 提升。

## 业务验收

- 自动床完整扫描/放置/引爆：17/17 原版客户端与集成服务器场景通过，含五个必须停止操作的场景。
- 爆炸回归：76 项检查，18 组实际伤害和 5 条操作链，包含普通床、TP 床以及恢复位置/角度。
- 字体缓存：13 项自动检查；36 组宽度、36 组视觉序列与四档缩放截图验证，像素保持一致。
- HUD 状态：34 项原生检查；ClickGUI：118 项检查。
- 实际世界计算测试：3,926 项检查；100 行战斗决策与既有基准一致。
- 相关详细记录：[床修复](bed-placement-fix-20261003.md)、[字体/HUD 性能](client-text-performance-20261003.md)、[GrimV3 研究](grimv3-client-review-20261003.md)。GrimV3 研究未改动 NoSlow 模式，也不声称通过所有反作弊。

## 发行要求

防护来自 rimeguard 官方 `v3.4.0` 标签（提交 `081dfd5`），其 Fabric 元数据 `custom.rimeguard` 为 `3.4`。原生和兼容模板均使用该版本；业务版本单独为 `1.2.11`。

发布必须完成生产 build、两通道 VerifyMerge、实际签名副本在 Microsoft 21.0.7 与 Adoptium 21.0.12.1 的启动和稳定运行验证、首次绑定与再次领取、下载内容/签名/哈希验证及三处分发同步。凭据、签名会员副本、生产密钥及内部混淆映射不入库或公开。

本次只更新默认 Minecraft 1.21.11；1.21.1 保留 Rime 1.2.10 / Rimeguard v3.4.0。会员通过登录器重新领取本人副本。GitHub 附件为发行模板，不是可直接启动的会员副本。
