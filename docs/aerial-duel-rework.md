# 实际空战复核中的修正

2026-09-19。此轮仍为候选开发，不代表已经全面超过旧客户端或通过反作弊验收。

在独立的 Minecraft 1.21.11 原版测试服上，两个真实远程客户端使用相同装备互相追击。旧端为用户提供的 SlimefunHelper 1.1.5.4，导入原始 729.nbt，连接经过本机 ViaProxy 3.4.13；新端原生直连。没有反作弊。测试辅助模组只用于配置、重置场景和记录服务器伤害，不进入发行包。

原候选的重锤对打失败，说明静止目标和几何回归通过不足以证明对战能力。复核后做出以下修正：

- 区分“正在接近下砸位置”与“已脱离滑翔的自然下落”。前者继续使用甲飞和烟花控制，后者仍禁止自动起飞、换装和补烟花中断蓄能。地形检查继续识别攻击下降意图，实际收翅仍由原有装备所有权与自然下落状态机控制。
- 收翅接近范围随双方相对速度调整，限制在 14–64 格。开始收翅仍须通过零至两 tick 延迟下均能命中的自然下落预测、碰撞、装备和状态检查；攻击距离没有扩大。
- 重锤的接近、收翅、攻击射线和脱离判断使用最新接收位置对应的包围盒，避免对客户端插值后的旧位置规划。沿用有界位置偏差过滤，未伪造实体位置或下落距离。
- 拉升与下降分两段预算。拉升终点按到达最高点的时间预测；下降阶段为匹配目标水平运动保留速度，并计入目标自身升降。此前按整个往返时间预测最高点，会重复计入目标在下降期间的移动。恒速几何测试已证明旧计算与两段交会解不一致；几何结果不当作实服提升百分比。

回归覆盖真实字节码接线、装备恢复和纯数学行为。`tools/combat-probe` 的原版游戏回归与外部双客户端实验分别保留原始日志。无反作弊直控试验和烟花驱动试验必须分别统计；不能把一种模式的胜局推广到另一种模式。

两份 SlimefunHelper 均声明 1.21.1。外部代理能建立连接，但不能替代客户端内 ViaFabricPlus 的矛出手接口。因此目前不把缺少完整 Via 组件的旧端长矛试验计为有效优劣结论。新参考端的 15 格/tick 是请求上限；其双视角功能有旧协议版本门，不能视为 1.21.11 的实测能力。

发版仍须完成同 SHA 的双 JDK、世界与 ClickGUI 启动验收，以及实际使用模式的重复对打。开发环境测试使用项目既有开发授权行为，不替代生产授权验收。

## 2026-09-19 实机阶段结果

客户端代码 `f906dcb`，原版 1.21.11 服务端，无反作弊。新版参考端为 SlimefunHelper v10.4.26，导入用户原配置后明确开启耦合巡航；本机外部协议代理的限制仍如上文。

| 场景 | 结果 |
|---|---|
| 直控速度 6、最低下落 4，对原始旧端 | 一轮胜；同代码烟花模式则败 |
| 直控速度 6、最低下落 4，对新版参考端 | 一轮败 |
| 直控速度 6、最低下落恢复默认 1.5，对新版参考端 | 三轮胜，分别 383 / 425 / 582 服务端 tick |
| 烟花模式、缩放 1.7 或 3.4，对新版参考端 | 未达到要求：败局或到时仍未有效反击 |

这些是固定出生位置的探索性试验，尚未交换起点或验证网络延迟矩阵。不能合并不同代码/参数轮次计算总体胜率，不能宣称全面超过参考端。请求速度不等于实际持续速度；逐 tick 净生命下降也不等于命中率或完整总伤害。

最终代码的隔离目标回归：MXS 在 800 客户端 tick 内产生 34 次服务器扣血，来源含重锤与长矛；高处起步的 SPEAR 在同长度场景产生 40 次长矛扣血。目标为无 AI、补满生命的服务器僵尸，不是玩家对打或本地 `.fakeplayer`。测试工具先清理复制世界中的已加载生物并关闭刷怪，再断言追击与观测目标 UUID 一致，以防遗留目标污染。

## rc.9：自定义拉升角的幅度修复与复测

目标接近正上方时，自定义拉升角原先用很小的水平误差重算 Y，同时缩短了请求向量。实际对打记录中请求从 6 降到约 0.1；回归例 `(0.06, 90, 0.03)` 在 45 度时复现 0.094868。现在只改变方向，保留原请求长度，再经过原有速度上限。默认角度 0、追赶阶段、终端精确控制及自然下落规则不变。该缺陷已修复，但不能据此宣称默认烟花追击速度或胜率提高。

主验收基准明确为用户指定的 `SlimefunHelper-1.21.1-1.1.5.4-yclimb-default8.jar.disabled` 加原始 `729.nbt`。参考 JAR SHA256 为 `1b70f13627d0c638a016b089e9d52c4a3b33c32ec1f920b9988ed95aa39c445c`，NBT SHA256 为 `d9eb60ef708057aea51c9ee1c11b55545777b51a69cb803f0d31f1bafd01088a`。后发的 v10.4.26 仅作额外参考，结果不混合。

旧端通过其原生 NBT 读取器与配置引用导入；本次成功复制 1043 项、528 个叶路径在该版本无对应引用。每局只由测试工具切换重锤模式、启用甲飞/追击并自动起飞，旧端其余参数沿用 NBT。双方使用相同无附魔装备、初始生命及烟花，20 TPS、无反作弊；原始配置不随仓库发布。

| 对 `.disabled` + `729.nbt` 的本次重锤复测 | 结果 |
|---|---|
| 当前烟花控制，速度请求 6、缩放 1.7、默认自适应 | 187 tick 败，无输出 |
| 同上，启用旧式垂直扩张 0.066 | 361 tick 败；交换起点后 207 tick 败 |
| 烟花缩放 3.4 / 5.0，其余同当前自适应 | 两轮均 1200 tick 超时；3.4 有重锤输出，5.0 仅记录到普通攻击扣血，均未证明超过旧版 |
| 直控 6、自适应高度 20、最低下落 1.5 | 393 / 307 / 579 tick 三轮胜；307 tick 轮交换起点 |

这些固定装备、低延迟重锤试验支持上述直控设置在该场景可用，不能证明全面超过旧版。直控胜局与烟花败局分别保留。两份参考端的长矛比较仍需客户端内完整 Via 组件；只有外部代理的试验不计入长矛优劣。

对应的部分配置放在 `presets/vanilla-mace`，使用说明见 `presets/README.md`。参数属于已测无反作弊场景，不调整全体用户默认值。

对额外 v10.4.26 参考端做过取样来源/corner-fill 两因素试验，四种组合均败，无伤害输出；未合入取样替换或全局 corner-fill。旧版 look × 1.72 不是“当前速度乘 1.72”；先前复核的高度差 2、最低拉升 3 的振荡例也不成立，两项已更正。另两轮因旧测试进程未退出、替换客户端被满服拒绝而作废，不计为修复版实测。测试辅助模组保留独立目录，不进入产品 JAR。
