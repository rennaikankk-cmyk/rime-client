# 实际空战复核中的修正

2026-09-19。此轮仍为候选开发，不代表已经全面超过旧客户端或通过反作弊验收。

在独立的 Minecraft 1.21.11 原版测试服上，两个真实远程客户端使用相同装备互相追击。旧端为用户提供的 SlimefunHelper 1.1.5.4，导入原始 729.nbt，连接经过本机 ViaProxy 3.4.13；新端原生直连。没有反作弊。测试辅助模组只用于配置、重置场景和记录服务器伤害，不进入发行包。

原候选的重锤对打失败，说明静止目标和几何回归通过不足以证明对战能力。复核后做出以下修正：

- 区分“正在接近下砸位置”与“已脱离滑翔的自然下落”。前者继续使用甲飞和烟花控制，后者仍禁止自动起飞、换装和补烟花中断蓄能。地形检查继续识别攻击下降意图，实际收翅仍由原有装备所有权与自然下落状态机控制。
- 收翅接近范围随双方相对速度调整，限制在 14–64 格。开始收翅仍须通过零至两 tick 延迟下均能命中的自然下落预测、碰撞、装备和状态检查；攻击距离没有扩大。
- 重锤的接近、收翅、攻击射线和脱离判断使用最新接收位置对应的包围盒，避免对客户端插值后的旧位置规划。沿用有界位置偏差过滤，未伪造实体位置或下落距离。
- 拉升与下降分两段预算。拉升终点按到达最高点的时间预测；下降阶段为匹配目标水平运动保留速度，并计入目标自身升降。此前按整个往返时间预测最高点，会重复计入目标在下降期间的移动。恒速几何测试已证明旧计算与两段交会解不一致；几何结果不当作实服提升百分比。

回归覆盖真实字节码接线、装备恢复和纯数学行为。`tools/combat-probe` 的原版游戏回归与外部双客户端实验分别保留原始日志。无反作弊直控试验和烟花驱动试验必须分别统计；不能把一种模式的胜局推广到另一种模式。

两份 SlimefunHelper 均声明 1.21.1。外部代理能建立连接，但不能替代客户端内 ViaFabricPlus 的矛出手接口。因此目前不把缺少完整 Via 组件的旧端长矛试验计为有效优劣结论。新参考端的 15 格/tick 是请求上限；其双视角功能有旧协议版本门，不能视为 1.21.11 的实测能力。

发版仍须完成同 SHA 的双 JDK、世界与 ClickGUI 启动验收，以及实际使用模式的重复对打。开发环境测试使用项目既有开发授权行为，不替代生产授权验收。
