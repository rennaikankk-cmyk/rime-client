# TP 水晶、锚、床与活塞水晶增强实测（2026-09-28）

基于本地 `05bfa11` 继续修改。本轮为源码改进和本机验收，尚未推送 GitHub、发布新版或替换官网与登录器的包。后续发布日志已准备在 `docs/release-next-combat.md`。

## 修改结果

- **TP 水晶**：最终评分改用真实碰撞形状及完整的可见防御属性；规划底座时计入未来黑曜石。引爆同时检查原位与临时站位的自伤和剩余血量，最多检查 18 个站位。临时放置高度避开原版两格高的实体占用检查。重复攻击按实体分别跟踪，弱化导致零攻击伤害时不提交无效攻击。旋转角度从眼睛位置计算；恢复数据在进入 TP 前保存。
- **锚**：同步与异步爆炸计算修正完全遮挡和半径边界的基础伤害；半径之外仍为零。移动预测扫过实际姿态碰撞箱，沿途检查自身风险，并读取既有的 GZBoost 只读速度预测。实测案例中原位自伤 1，路径中达到 20.6，能在动作前拦截。
- **床、TP 床**：共享上述基础伤害修复；TP 引爆搜索可达安全位置，检查临时位置的自伤。保留原版对床朝向的要求；关闭旋转时不额外转向瞄准引爆。往返恢复进入前的坐标与角度。
- **活塞水晶**：目标遮挡按当前地形计算，可破坏掩体的额外风险仅用于自伤。上界筛选遵循与最终选点相同的红石复用优先级，避免误删低伤害但更优先的复用方案。最终引爆重新读取目标防御并计算真实水晶位置的伤害；零攻击伤害时不提交攻击。

`GuangxiCrystalModule`（包括 Rusher）、`GuangxiElytraModule`、`RotationManager`、旧 `PredictUtil` 与基线逐字节规范化比较一致。本轮没有改授权、心跳、水印、混淆或保护配置。

## 回归与边界

`gradlew --offline --console=plain check` 成功，**85 个回归测试任务全部执行通过**。其中覆盖爆炸时序、伤害模型、异步规划、攻击提交、取消恢复、武器弱化、授权入口及耦合巡航；新增锚的完全遮挡、半径内外边界检查。未制作或部署发行 Jar。

实机目标为服务器拥有的固定僵尸，夹具调用生产动作方法；生产的玩家寻敌过滤保持原样。活塞测试预先搭建机构，验证实际推动与攻击，没有宣称完整自动搭建或真人 PvP 对局。动作测试的驾驶玩家使用创造飞行和抗性 V 隔离伤害及击退，伤害对照目标仍承受真实服务器伤害。

原版不会向客户端完整公开其他实体的药水效果。“已知抗性”对照明确向测试客户端发送了效果元数据，仅验证已知抗性的计算，不能证明能识别实战中的隐藏药效。未测试 200 格 TP、旧协议服务器、高延迟多人对战、长时间帧率或所有战斗模块与 GZBoost 同时运行的极限速度。

早期调试运行用于修正夹具的床朝向、药效可见性、击退干扰和活塞目标站位等条件，未计入通过证据。最终验收只引用完整成功的 final01，详细数据、测试输出和源码摘要保存在附带证据包中。

复现入口：`tools/blast-probe/run-probe.ps1`；说明见同目录 README。运行必须使用新的测试目录名，原测试世界不被改写。测试 Jar 仅包含夹具；客户端开发豁免仅在显式开发启动中启用。
