# GuizhouWare 1.3.1-rc.17

Minecraft 1.21.11 / Fabric / Java 21。2026-09-20 内部测试版。

## 相对官网 rc.16 的变化

- 长矛接敌方向、距离判断与甲飞实际攻击眼高一致；蓄力就绪且接近刺击范围时缩短前进步长，减少穿过有效机会。可见且有效的接敌机会最多保留两 tick，明确武器威胁仍可打断。MXS 的长矛阶段共享这些改动。
- 重锤拉升规划保持配置的蓄能高度下限，避免过低规划使下一轮砸击难以蓄能；不把客户端预测当作实际伤害。
- 正常甲飞在移动发送后的 POST 边界尽早返回胸甲，保留末尾恢复路径与重锤装备优先权。没有增加换装次数；修正与起飞恢复期间的鞘翅窗口仍保留。
- 空战 HUD 按已选网页原型调整布局、字体、图标、雷达和层间动画；修正目标切换、透明度、缩放与数据含义。Fullbright 延后捕获亮度选项，修复启动恢复时选项未初始化的问题。
- 保留现有混淆、账号水印、设备绑定、签名心跳和诊断开关。客户通过登录器取得本人授权版本。

## 本地同模式验证

对手为原始 `SlimefunHelper-1.21.1-1.1.5.4-yclimb-default8.jar.disabled` + `729.nbt`，不是 v10.4.26。双方初始生命、装备、图腾和消耗品一致，AutoTotem 均开启；旧端保留原参数，新端使用被测候选配置，策略参数并非逐项相同。旧端通过本机 ViaProxy 接入同一 1.21.11 服务端。

24 场 SPEAR 对照覆盖正面、斜向和 60 格可见远距离，交换出生侧并反转第二轮顺序。原逻辑 7 胜 5 负，接敌候选 11 胜 1 负；新端图腾消耗由 19 降至 14。这个结果只支持这些本地场景中的组合改善，不能换算成所有服务器的胜率或命中率。

另外 12 场回甲时序对照中，两组各含 4 场 SPEAR 和 2 场 MACE；MACE 各 2 胜且没有掉血或消耗图腾。正常回甲的客户端发送间隔缩短约 0.07 ms，不等于服务端减伤比例。原旧包没有 MXS，未提供虚构的 MXS 同模式战绩。

候选功能提交 `406b5f2` 完整构建与 10177 项混淆校验通过。正式版本构建、同包双 JDK 启动和部署校验记录随发行产物保存。公网延迟、复杂地形、Grim 实服与客户机器仍需回传验证，不承诺所有场景全面胜出。
