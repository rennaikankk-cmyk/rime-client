# 客户端公共文字路径优化

基线：`d4a537866b6caeb3b4ae0a64a8fb9e7651ae6d10`，Minecraft 1.21.11。本轮改动覆盖使用自定义 FontRenderer 的 ClickGUI、HUD、Nametag 等文字路径，以及 HUD 常驻状态查询，不修改战斗算法、攻击频率、选点范围或进食/背包发包逻辑。

## 改动

- 每个字体实例缓存短文字宽度与视觉排版，分别最多 512 项、每条最多 256 UTF-16 单元，LRU 淘汰。变化的坐标/FPS/玩家文字不会无限增长；长文字正常即时计算。
- 视觉排版按文字、默认颜色及当前 Minecraft Language 对象验证，语言重载时清空。颜色代码、重置、双向顺序仍经过原解析器。
- 字体关闭/GUI 缩放重建同时清理测宽、排版与 glyphPages 记录；避免每次缩放后在后续绘制中继续遍历已销毁纹理对应的空列表。锁顺序保持与绘制一致，关闭后允许正常重新初始化。
- 绘制和 formatted measurement 不再为每个 code point 分配 `Character.toChars` 数组，保留原有 UTF-16 字形查找顺序，包括代理对。

## HUD 状态查询续改

- 旧配色迁移只在首次使用、相关颜色设置事件、配置导入或重新启用后检查。迁移自身的设置事件可以触发一次补充检查；稳定状态不再每帧扫描 43 个颜色设置。
- 按类型查找元素缓存成功的首次匹配，仍保持基类查询的注册顺序。开关值每次读取，不缓存开关、位置或当前帧边界。
- 不变的 HUD 元素列表复用同一不可修改列表，减少编辑器每帧多次复制。注册时自动失效。
- 颜色与透明度每次读取实际设置，只有值变化才创建新的 HudAppearance；缓存仅 13 个已注册元素，没有时间节流。

`tools/hud-state-probe` 在基线 HUD 实现和候选实现上使用同一测试 jar，各通过 34 项真实模块/配置/事件检查。覆盖精确类型与基类查询、开关、颜色 alpha、透明度、导入旧配色/自定义颜色、关闭期间静默改色后重新启用。

50,000 次稳定 HUD 状态遍历的五次批量调用中位数：27.8376 → 15.0364 ms，约减少 46%。这是包含全部 13 个元素的状态访问微基准，不是整帧性能；本轮没有把它折算成 FPS。原始数据在 `work/hud-state-lab/{baseline,candidate}/results.json`，汇总 `comparison.json`。
