# 水晶、TP 水晶、床与客户端开销优化

基线：`3e59ceb6e7fd0c5c66a5307dee37319b48b19769`。按用户确认，仅新增实用、稳定的缺失功能。

参考：[GzSakura1338/OpenTroll-Recode](https://github.com/GzSakura1338/OpenTroll-Recode/tree/3d4f1eeaf95f580f116ea553a309e02403ebf114)。用户提供的 `GzSakura1337` 地址未找到，实际可访问仓库所有者为 `GzSakura1338`。对照锁定提交 `3d4f1eeaf95f580f116ea553a309e02403ebf114`；参考工程的源码含反编译恢复与未完成实现（见其 `KNOWN_ISSUES.txt`）。本次用 Rime 的 Mojang 映射、事件总线、换槽管理器与授权机制重新实现选定功能。

## 计算与放置

- 水晶、床、TP 水晶复用同步扫描中的方块状态、碰撞形状和包围盒采样点，降低重复读取及对象创建。保留原有包围盒网格与射线判定，不缩减采样点。
- TP 水晶每轮只扫描一次可炸水晶，复用于循环状态和攻击选择。没有到达动作间隔时提前返回；用完全无遮挡时的伤害上界排除无法达到最小伤害或无法胜过当前候选的位置。
- 床新增 `VerticalScan`（默认 1，范围 0–3），支持目标脚部上下层候选；可替换方块纳入候选。选择前检查实际可点击的放置面，减少被不可交互候选占住的情况。
- 床伤害缓存同时包含床头、床尾，防止同床头不同床尾共用错误的自伤结果。伤害计算仍移除两个床方块。
- 保留 `3e59ceb` 的 Rotate 关闭时沿当前方向放床且不等待转头的行为。选点后手动改变朝向会放弃旧候选，下轮重新选择。
- 缓存仅限客户端线程的一次扫描。最终放置、爆炸、TP 临时位置仍检查当前伤害、安全条件、实体状态和授权；切服、包回调和新扫描重新取状态。

## 客户端开销

- 事件总线用不可变监听数组发布订阅快照，热路径遍历不再创建迭代器；保持优先级、取消和异常隔离行为。
- ActiveModules HUD 每 50 毫秒更新名单、文字宽度和排序。绘制及动画保持逐帧，模块切换与设置事件立即使缓存失效。
- 水晶延迟与物资条件不满足时不再做本轮移动预测和实体扫描。
- 新增后台帧率限制；只在窗口失焦且模块开启时生效，保留原版更低的限帧结果，不修改视频设置。
- 修复 bundle 子数据包被取消后仍交给原版处理的问题，使声音限流能覆盖打包声音。

## 新增模块（均默认关闭）

| 模块 ID | 中文名 | 行为与边界 |
| --- | --- | --- |
| AntiBot | 假人过滤 | 在共享目标策略中检查玩家列表、名字格式，两项可分别关闭 |
| AntiLevitation | 防漂浮 | 移除客户端漂浮效果 |
| AutoCenter | 自动居中 | 碰撞检查、超时与切服重置 |
| AutoFish | 自动钓鱼 | 自己鱼漂附近的上钩声音；延迟收竿、重抛；拒绝旧世界回调 |
| AutoJump | 自动跳跃 | 默认仅移动且落地时跳跃；打开界面、使用物品、潜行时暂停 |
| AutoRespawn | 自动重生 | 每次死亡只发一次重生请求 |
| AutoTool | 自动工具 | 手动挖掘选择最快快捷栏工具；保护低耐久工具；仅归还自己持有的槽位 |
| AutoWalk | 自动前进 | 界面、手动后退、卡顿或近期位置修正时暂停；不保留按键状态 |
| ChestStealer | 容器拿取 | 一次间隔一个 QUICK_MOVE；仅储物菜单；检查空位、光标及换槽占用 |
| ItemSaver | 耐久保护 | 按耐久百分比换工具或收起工具；不丢弃物品；AutoTool 遵守保护条件 |
| LagNotifier | 卡顿提示 | 本地提示服务器停止发包与位置修正；不发送聊天消息 |
| NoSoundLag | 声音限流 | 统计普通声音与实体声音数据包；默认每秒最多 80 个 |
| SafeWalk | 边缘保护 | 地面上的原版边缘裁剪，不修改潜行按键状态 |
| ViewLock | 视角锁定 | 开启时记录视角；水平、垂直角可分别配置 |
| UnfocusedFps | 后台帧率 | 默认后台 30 FPS，范围 1–240；需手动开启 |

配置 ID 保持英文稳定键，标准显示名、说明及新增设置有中英文呈现。自动动作保留授权检查；失效或关闭仍允许清理待执行动作与归还槽位。

本批暂不纳入大量聊天、娱乐、录包模块，也不替换现有飞行、1.12 协议、授权及启动器逻辑。参考仓库没有适合直接替换本仓床与 TP 循环的完整实现，因此保留并优化本仓确认序列。

## 验证与实测边界

- `gradlew.bat check --offline`：完整客户端回归通过。
- 新增采样几何与 bundle 取消/顺序回归；新增工具授权路径与混淆后检查。
- `gradlew.bat build --offline`：包含回归、重映射、ProGuard 和 `verifyObfuscatedJar` 验收。
- Java 21 开发客户端实际启动，日志出现 `Initialized Rime in ...ms`、98 个模块注册、声音引擎和完整纹理图集创建；测试实例正常关闭。使用仓库允许的 `-PgzwDevelopmentBuild=true`，打包仍使用正常参数。

未做多人服务器战斗或同场景 A/B FPS 实测，不能给出提高百分比。用于实测的新增计数器：`combat.exposure.blockReads`、`combat.exposure.sampleBuilds`、`combat.blast.damageCache.hit/miss`；TP 新增 `combat.GuangxiTP.breakScan` 耗时。可用现有 `diag start 30`、`diag export`、`timings` 命令在相同场景比较扫描耗时、HUD 帧间隔与 GC。

构建产物是客户端本体，正式客户发行仍按现有 rimeguard 合并、native 壳和 VerifyMerge 流程执行。
