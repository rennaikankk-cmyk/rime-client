本轮修复旧协议中映射成剑的长矛读取、持续使用与动作，并完善 GZBoost 下的重锤窗口和长矛瞄准。双方实际 Via 目标 1.20.3–1.20.4（765），Paper 1.21.11 build 132、ViaVersion/ViaBackwards 5.12.0、ViaFabricPlus 4.4.15、GrimAC 2.3.73、PacketEvents 2.14.0；无 Grim 豁免。

- 两批均为预先固定的十组换边场景，要求至少 15/20 胜。双方装备、20 生命、2 图腾、64 烟花、模块设置相同。帧率上限均为 60，并检查实际 FPS/TPS、765 协议、双视角发包、非豁免 Grim 检查、服务器伤害和死亡。
- 原样旧版无法在此 Via 链路使用长矛的兼容预检不计入策略胜率。此前长矛独立候选 holdout4 为 12 胜 8 负（未达门槛）；此前重锤独立候选 holdout1/2 为 4 胜 7 负 9 平及 9 胜 8 负 3 平。全部败局、平局、运行故障、调参和恢复记录保留，各批不混算。
- 候选/对照源码与实际主类开战前冻结，结束后验证一致。完整 check 在独立长矛验证前通过 113 项任务。最终长矛改动只在长矛阶段生效；移除精确列明的长矛增量后，重锤业务源码与已验收的 4e290fa 完全一致，重锤回归断言也保持不变。

这些是固定环境下的自动对决样本，不能推广为真人或所有服务器胜率。记录保留 Grim 检查、违规和回拉；不宣称零违规。血量下降没有完整计入吸收伤害，不能作为总 DPS；死亡掉落不算战斗消耗。

## Via 长矛兼容

仅当实际 Via 连接、协议家族和原始物品标记匹配时读取。优先采用 `VB|Protocol1_21_11To1_21_9|id`，避免多阶段转换把 `VV|original_hashes.id` 覆盖为剑编号。严格匹配七种材质及原始编号；普通剑、改名剑、不对应材质和未知标记不启用。

使用独立只读的原版长矛蓄力、范围、移动效果参数视图；保留 Via 存下的服务器参数覆盖，不改背包组件或校验哈希。补旧协议客户端持续使用、使用动作和移动效果，服务器仍负责原版长矛判定。测试覆盖实际原始 1302 + 外层剑编号 883、七种材质、服务器覆盖和错误输入。

参考用户提供的 SlimefunHelper 样例只作 ZIP/字节码读取，未执行。样例 SHA256：`1b70f13627d0c638a016b089e9d52c4a3b33c32ec1f920b9988ed95aa39c445c`。本轮没有移植其旧协议左键刺击包或剑模型替换；外观仍可能显示 Via 的剑模型。

## 长矛策略

真实服务器诊断发现，蓄力样本仍为滑翔姿态、0.4 格眼高，甲飞循环拥有装备不代表服务器已站立。长矛导航、交会和瞄准改为共用当前真实姿态眼睛，避免站姿起点偏差；重锤保留原路径。

在目标可见且自有长矛已就绪的闪避窗口保留瞄准；短距离侧向反击保持造成原版伤害必需的正向速度，路径检查、撤退、珍珠和重锤威胁优先。实际支持双视角的 Via + GZBoost 环境中，从移动后的眼睛补短距离瞄准包；沿用所有权、授权与发送取消入口，没有改位置、伤害、冷却、服务器 TPS 或 RusherHack/RotationManager 核心。

本地完整证据位于 outputs/1.2.5空战优化验证/holdout3 与 outputs/1.2.5长矛兼容验证/holdout5。哈希清单、完整原始对战、兼容预检、姿态诊断和失败候选随记录保存。
