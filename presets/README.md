# 飞行和原版服重锤配置

`manual-coupled-cruise` 是独立手动耦合巡航预设，包含甲飞、速度日志和地形防护，关闭追击与 AutoFly。复制整个文件夹到 `guizhouware/configs/`，保存原配置后执行 `.configs load manual-coupled-cruise`，再手动开启飞行。参数和控制权说明见 `docs/coupled-cruise.md`。此预设不替换下面已对打验证的重锤配置，也没有新增空战胜率结论。

`vanilla-mace` 对应 2026-09-19 在本机无反作弊 1.21.11 服务器上验证的直控设置：速度 6、自适应拉升高度 20、最低自然下落 1.5。对用户指定原始 `.jar.disabled` 加 `729.nbt` 的三次重锤对打获胜，其中一次交换起点。装备与低延迟条件见 `docs/aerial-duel-rework.md`。它不是烟花模式或 Grim 服务器的验收结果。

把整个 `vanilla-mace` 文件夹放入游戏目录 `guizhouware/configs/`。可先用 `.configs save before-air-test` 保存现有配置，再用 `.configs load vanilla-mace` 加载。加载后主动开启“鞘翅追人”；飞行与甲飞由追击按需启动。预设只配置上述两个模块，不包含账号、授权、服务器列表或按键绑定。

独立“甲飞”模块仍可单独使用；它负责装备切换，飞行速度与方向由飞行控制模块管理。此预设没有自动开启独立甲飞。

## 保留烟花补给的原版服设置

`vanilla-mace-rockets` 使用 `FIREWORKS`、速度 6、`AutoRescale=false`，保留自动补烟花，关闭本地烟花包络缩放。关闭缩放后直接应用请求速度，不能将名称中的 FIREWORKS 理解为原版物理速度或反作弊兼容保证。`RescaleAmount=5` 在此预设下不参与速度计算。

在 rc.10（97a52d6）上，使用用户指定的原始 `.disabled` 加 `729.nbt`、相同无附魔装备和低延迟本机服务器，6 次重锤对打获胜，含 3 次交换起点；耗时为 671、457、390、299、402、461 服务端 tick。试验未启用修改规划速度/拉升高度的外部实验开关。这是固定场景的结果，不表示对所有配置、服务器或长矛模式必胜；逐局证据与限制见 `docs/aerial-duel-rework.md`。

同样先保存现有配置，将整个 `vanilla-mace-rockets` 文件夹复制到 `guizhouware/configs/`，执行 `.configs load vanilla-mace-rockets`，再手动开启追人。两份预设都是部分配置：没有列出的设置及其他模块沿用当前配置；若有其他战斗模块抢占武器或移动，不能视为复现了上述对打条件。它们不更改客户端全局默认值。

后续扩大起点场景后已经出现败局：45 度斜向起点、己方低于对方 24 格、低空换边均各有一局失败。因此这份预设只能作为已测原版服对比起点，尚未达到全面超过旧版的要求。

## 完整拉升 20 格的原版服设置

`vanilla-mace-height20` 在上面的烟花补给设置基础上，将 `MaceAdaptive` 设为 `false`，保持 20 格拉升目标，避免按较短拦截预算将高度压低。真实最低下落仍为 1.5；20 格是相对拉升目标，不等于每次命中都积累了 20 格下落。

统一两端帧率上限 60、视距 4、模拟距 5 后，该配置在斜向起点、己方低于对手 24 格、低空、斜向换边四局获胜，分别 177/307/214/110 服务端 tick；净生命下降记录均为 0。先前帧率未统一时的两局也获胜，分别 194/293 tick。这些有限样本仍未覆盖高延迟、附魔、持续逃跑和完整旧端长矛。

将 `vanilla-mace-height20` 文件夹复制到 `guizhouware/configs/` 后，保存旧配置并执行 `.configs load vanilla-mace-height20`，再开启追人。这是当前有实测支持的原版服重锤试用配置；其他模式及模块设置沿用原配置，参数不会自动适用于所有服务器。

## 独立甲飞入口

甲飞现在只由 Movement → 甲飞（ArmorFly）控制。上述预设加载时保持甲飞关闭；需要换甲飞行时先启用独立甲飞，再按各预设说明开启追人或飞行。旧配置迁移保留已启用的甲飞；原先关闭飞行的配置不会因迁移自动开始换甲。
